# Conversación con IA — Mejora de documentación con Sphinx

**Fecha:** 15/09/2026  
**Herramienta:** GitHub Copilot  
**Proyecto:** Global Exchange

## Contexto

La documentación técnica se generaba con Sphinx, pero utilizaba el tema Alabaster, no tenía una portada de navegación suficientemente clara y declaraba una carpeta `_static` que todavía no existía. Eso producía una advertencia durante la compilación y dejaba la visualización sin una identidad propia.

## Conversación simulada

**Desarrollador:** La documentación generada debe leerse correctamente y tener una presentación más cuidada.

**IA:** Se revisaron `conf.py`, `index.rst`, la referencia automática y las dependencias existentes. El proyecto ya incluía `sphinx_rtd_theme`, por lo que se reutilizó esa dependencia en lugar de incorporar otra.

**Desarrollador:** ¿Qué se cambió?

**IA:** Se actualizó la configuración para:

- Usar `sphinx_rtd_theme` con navegación expandida y profundidad controlada.
- Configurar títulos HTML, idioma español y opciones de autodoc más legibles.
- Activar `autodoc_typehints` en la descripción y separar las firmas de clases.
- Cargar `custom.css` desde una carpeta `_static` real.
- Ocultar el enlace técnico de código fuente de la interfaz de documentación.

También se renovó la portada `index.rst`, se agregó `guia.rst` con la arquitectura, el flujo de autenticación y el flujo de divisas, y se renombró la entrada principal de referencia a `Referencia API`.

## Mejora visual

El CSS personalizado define una identidad teal y neutra, mejora la jerarquía de títulos, resalta admoniciones y tablas, usa tipografías diferenciadas para texto y código, y mantiene una presentación responsive compatible con el tema Read the Docs.

## Verificación

La documentación se generó con:

```text
.\\.venv\\Scripts\\python.exe -m sphinx -b html docs/source docs/build/html -W
```

Resultado: compilación exitosa, sin advertencias, con las páginas HTML generadas en `docs/build/html`.
